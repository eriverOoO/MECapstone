# 칩 위치 필터 및 세 가지 업무 상태 재검사

검증일: 2026-10-26. 이전에 사용한 원본 13장 + 변형 156장, 총 169장을 다시 처리했습니다. 이전 ROI 재검사의 `nominal_roi` 및 여유 폭을 그대로 재사용했습니다. 입력 이미지·ROI를 새 결과에 맞춰 변경하지 않았습니다.

## 구현한 변경

원근 보정한 카드 좌표에서 칩 후보 **중심점**이 넉넉한 예상 영역에 있는지 검사합니다. 설정 기준 영역은 `[0.12,0.32,0.32,0.58]`이고 x 여유 0.02, y 여유 0.04를 추가했습니다. 실제 허용 영역은 왼쪽 `[0.10,0.28,0.34,0.62]`와 이를 180도 회전한 오른쪽 `[0.66,0.38,0.90,0.72]`입니다. 후보 전체가 영역 안에 들어갈 필요는 없습니다.

이 수치는 현재 프로젝트의 조정 가능한 영상처리 기준이며 ISO의 치수를 그대로 옮긴 값이 아닙니다. 오른쪽 기구 투입구를 사용했고, 카드의 글자 방향으로 정·역방향을 판단하지 않습니다. 예상 영역 밖 후보는 점수가 높아도 칩 후보 순위에서 제외하며, 그 위치와 점수는 `rejected_chips`에 남깁니다.

위치 필터만 넣으면 실제 칩을 못 찾았을 때 앞면을 뒷면으로 추정하는 오류가 늘어났습니다. 금색 바탕에 금색 칩이 있는 경우에도 접점 외곽을 찾을 수 있도록 그레이스케일 경계 후보를 추가했습니다. 기존 후보와 겹치는 같은 칩의 경계는 중복을 제거합니다.

|---|---:|---:|---:|
| 처리 이미지 | 169 | 169 | 169 |
| 카드 검출 표시 | 107 | 107 | 107 |
| 칩 검출 표시 | 64 | 40 | 52 |
| 실제 뒷면 91장에서 칩 검출 표시 | 19 | 2 | 2 |
| 실제 뒷면을 앞면 방향 상태로 분류 | 10 | 2 | 2 |
| 실제 앞면을 뒷면 추정으로 분류 | 4 | 12 | 0 |
| UNKNOWN | 123 | 120 | 120 |

칩 검출 표시는 정확도가 아닙니다. 실제 카드가 6종류의 앞면과 7종류의 뒷면으로 보이는 것을 원본에서 확인한 기존 검토에 기반한 집계입니다. 같은 원본의 변형이 많고, 전부 개발에 사용한 이미지이므로 새로운 카드에 대한 성능 추정치가 아닙니다. 칩 박스의 정답과 IoU를 계산한 검사는 아닙니다.

## 최종 판정 건수

| 표시 | 코드 | 건수 |
|---|---|---:|
| 앞면 정방향 | FRONT_CORRECT / CORRECT | 6 |
| 앞면 반대방향 | FRONT_REVERSED / REVERSED | 27 |
| 뒷면 추정 | BACK_LIKELY / CHIP_NOT_VISIBLE | 16 |
| 판단 보류 | UNKNOWN | 120 |

**뒷면 추정은 뒷면 확정이 아닙니다.** 카드가 보이고 화질·자세 조건을 만족한 상태에서 유효한 칩을 찾지 못했다는 뜻입니다. 실제 앞면의 칩을 놓치는 경우에도 발생할 수 있으므로 기존 뒤집기 1회 제한과 재촬영 로직을 유지했습니다. 세로 카드, 카드 외곽 실패, 낮은 화질 등은 강제로 세 업무 상태에 넣지 않습니다.

오른쪽 투입구에 긴 변을 맞춘 조건으로 해석할 수 있는 8개 원본의 104장에 대해서는 원본의 칩 유무와 키트의 회전 정보를 기준으로 방향 라벨을 만들었습니다. 이전 25/104장, 이번 47/104장이 라벨과 일치했습니다. UNKNOWN도 불일치로 계산했습니다. 세로 원본 4개와 기울어진 `plain_back` 원본 1개의 65장은 이 방향 정확도 계산에서 제외했습니다. 이 라벨도 같은 개발 데이터의 검토용이며 독립적인 벤치마크가 아닙니다.

## 대표 사례와 남은 오류

- Aircash 뒷면의 홀로그램은 허용 위치를 벗어나 제외되고 뒷면 추정으로 바뀌었습니다.
- Piraeus Visa 앞면에서는 오른쪽 비접촉 결제 아이콘을 제외하고 왼쪽 실제 칩을 경계 후보로 찾았습니다. 이전 CORRECT 오판이 앞면 반대방향으로 바뀌었습니다.
- Piraeus Mastercard 뒷면의 홀로그램도 위치로 제외했습니다. 다만 카드가 세로여서 기구 방향 판정은 UNKNOWN입니다.
- **SBI 뒷면 원본과 dim 변형 2장에서는 홀로그램이 허용 위치 안에 들어가 여전히 칩으로 오검출됩니다.** 위치만으로 구별할 수 없어 접점 구조 검증이 추가로 필요합니다.
- 카드 외곽 검출 문제는 이번 범위에서 수정하지 않았습니다. 카드 검출 표시는 107/169장으로 동일합니다.

색상: 보라 = 칩 허용 위치, 빨강 = 위치로 제외한 후보, 노랑 = 남은 후보, 파랑 = 카드, 초록 = 기존 검사창. 노란 후보도 품질/점수 조건을 통과하지 않으면 칩 검출 true를 의미하지 않습니다.

## 실행 및 파일

프로젝트 폴더에서 원본 데이터가 준비된 상태로:

```powershell
.\python.ps1 tools/retest_chip_positions.py
.\python.ps1 -m unittest discover -s tests -v
```

본 PC에서 **46개 테스트 통과**했습니다. 1개 테스트는 선택적으로 다운로드한 실제 카드 이미지를 사용하며, 원본이 없는 새 환경에서는 그 테스트를 건너뜁니다.
